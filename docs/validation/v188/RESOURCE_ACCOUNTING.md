# v188 固定完整域的必要分配下界

结论：v187准确运行包完成原域初始化至少需要 **8,743,123,908字节（8.142668668 GiB）**。它超过原地址空间上限8,589,934,592字节约146.09 MiB。该数不是失败时RSS，也不是完整运行峰值或足够资源的承诺。8GiB下当前包不可行；此前“总需求尚未闭合”现已收敛为这一明确的否定结论。

源码、配置、既有ABI与逐行算式见[核算报告](evidence/resource01/report.json)和[源码摘录](evidence/resource01/source_excerpts.json)。准确源f53f4609a0331d48efee69a4e4f3c3598378cc03，LDC1.41.0实数包SHA256为d904a4079838eefcfe9f7e424b6dd2bba5c88e671b19ca796c8fc645622ae08b。实际运行包覆盖层、上游源分别核对；不重新编译或运行类型查询。

## 1. 计数与范围

N=705490内部单元，G=26324边界ghost，C=N+G=731814；F=1741600全部面，V=335726顶点。原网格包含70574四面体和634916棱柱，因此CV=4091792单元—顶点关联、CF=3456876单元—面关联。FV只用3F=5224800作为面—顶点关联下界，实际四边形的第四个顶点尚未计入。

配置保持二阶插值、非扩展模板、黏性最小二乘/单元位置、单组分热完美空气、Wilcox及四个时间层；准确编译保留multi_species_gas与newton_krylov。两类边界均构造有数据的ghost。原壁19752面/面积1.9646292565715551m²、最低19层和尾缘不变。

## 2. 计账方法与去重

| 部分 | 下界/字节 | 解释 |
|---|---:|---|
| 既有v187必要载荷 | 6,976,609,424 | 展开为13行；不把旧合计当作不可核对的常数 |
| 新补齐有效载荷 | 1,419,942,906 | 顶点、拓扑、邻域、气体缓冲及额外核心数组 |
| 有效载荷合计 | 8,396,552,330 | 约7.82 GiB，未计任何分配余量 |
| 已知小分配最低取整差 | 346,571,578 | 准确GC尺寸类别；未计全部分配开销 |
| 必要分配合计 | **8,743,123,908** | 约8.14 GiB，超过8 GiB |

FluidFVCell、FVInterface等的inline尺寸取自v187成功ABI查询；顶点/网格类没有新查询，分别用未填充字段和137/65/76字节，再按GC最小176/96/96字节取整。这些不是声称实测的classInstanceSize。相比草稿采用对齐后144/72/80字节，最终分配下界相同。

关键独立分配及别名处理：

- FluidFVCell中的fs/grad/ws/几何/U等指向dense数据，不重复计算相同有效载荷；U/dUdt各四个切片描述符是另行分配，Qudf也是独立数组。类内切片字段已包含在680字节内，不再次计入。
- 原UnstructuredGrid在整个初始化后仍被块持有。USGFace/USGCell拥有自己的索引数组；求解器后续另建vtx/iface/outsign引用和dense c2v/c2f/outsigns，构造过程明确使用追加或复制，不能当同一数组。
- 五类dense外层slice为face_distances、cell_cloud_indices、c2v、c2f、outsigns；其内层元素另外计。halo两个外层slice只计描述符，未假定其内层非空。
- interpolation cell_cloud包含自身与每个邻面单元，dense cloud_indices只含邻居；viscous cloud_pos/cloud_fs是另外两组指针。它们不重复计被指向的流动对象。
- 顶点pos/vel、new FlowGradients及massf是独立动态分配；顶点未分配WLSQ工作区，不计该工作区。grid.vertices和求解器FVVertex数组并非同一对象。
- FlowState的288字节包含GasState结构本身，但不包含其massf/rho_s数组。单组分各8字节。面jx/jy/jz/hs是另外四个数组；梯度massf及插值梯度rho_s/Phi/Max/Min也分别计。
- v187旧faceNamedCoreArrays对dL/dR各只取8字节，是有效的部分下界；本轮按Vector3各24补32F，不追改旧证据。另补48F stencil与72F L2R2数据。

GC准确源码在请求≤2048字节时使用smallAlloc/binTable。尺寸类别为16、32、48、64、96、128、176、256、368、512、816、1024、1360、2048。680字节类至少816，8字节数组至少16，24字节至少32，56字节至少64，顶点200字节梯度至少256。本轮只加这些确定差值；数组元数据、扩容容量、页空隙、GC池余量、运行库/映射/栈、临时读写缓冲及后续求解分配均未计。

## 3. 独立分组复算与检查限制

把行账按所有者重新归并，必要分配为：

`6064*C + 1930*F + 576*V + 250*N + 32*CV + 92*CF + 24*FV = 8743123908`。

其中C项包含dense单元物理/工作区/对象/ghost及其已知取整；F项包含dense面/对象/原网格面及取整；V项包含顶点/原网格坐标/外层关联；N项为内部单元独有外层描述符等；CV/CF/FV项为独立拓扑与邻域关联。此分组与逐行账一致，但它仍是同一源码模型的独立算术复核，不冒称另一求解器或实测峰值验证。

资源检查16项拒绝覆盖错包、错网格/面积/类型、非法预算及真实启动前拒绝。较大预算只得到not-excluded-unproven，runAuthorized始终false；下界不能开放旧候选。准备入口的旧大输入哈希使用既有回执替身，没有重读大网格/初场，不称旧来源重新验证。小例只检查原分派仍走原包审核，未重跑小例或完整旧审核。

首版测试误用入口参数签名，0.004603秒失败，父0.438784秒；准确源和失败保持。修正调用后0.048382秒/父0.323571秒通过，无原生任务。核算0.097031秒/父0.162039秒通过；三父合计0.924394秒，≤120秒程序预算，开发/源码阅读/协调墙钟另计。

## 4. 本机与替代布局结论

主机约16GiB、WSL memory=8GB/processors=2/swap=2GB保持。原生候选另设8GiB地址空间上限，交换空间不能绕过该地址空间限制；WSL物理内存与进程地址空间不是同一指标。失败RSS采样峰6.58GiB低于完成初始化下界不矛盾：分配尚未完成，RSS也不等于全部虚拟映射。仍不知道失败请求大小、准确应用行和峰值虚拟空间，不为补这些信息重跑。

固定源码中的Eilmer4并非已证明可用替代：它仍为每单元保留112点/2688字节插值工作区，使用独立顶点/面/单元对象；没有完整布局、变cp/Wilcox/边界及原面相容证据，也没有8GiB可行证明。因此不直接切换、构建或试跑。MPI在同机分区不自动降低总组内存。SU2历史低内存运行不能消除其既有物理/收敛失败。

当前没有闭合的本机替代方案。**关闭当前包在8GiB下的完整域入口，不再追加存储诊断版本。** 可考虑32GB以上主机、为求解器保留16GiB作为下一次开发资源规划起点，但这只是带余量的建议，不是已证明的最低硬件要求或收敛保证。须先确认实际可用环境，再登记有上限的唯一初始化/发展候选；不能直接把本机WSL改到16GiB。
