# v174 保存场开发温区守卫事前计划

本项仅实现和审核原生 IDEAL_GAS 的已保存场观察，不运行 CFD、不构建引擎、不遍历实际大场。独立测试总上限 60 秒、4 GiB，自动追加 0。主运行候选预算另由主 PLAN 登记。

固定开发域为闭区间 150–360 K。每个具名 CSV/VTK 配对由一个自有异步 helper 检查，单次最多 15 秒、累计最多 60 秒；异常或超时成为 guardError，越域成为 modelDomainExceeded，均不冒称用户取消。runner 自行停止其原生子进程，守卫只回收自己创建的 helper。所有回执直接保存在任务目录，计入既有输出容量。

准确单区 steady writer 不是原子发布：串行同步写基名及编号名，关闭文件后返回；最终 Output 可能再次覆盖最新编号名。因此运行中只观察连续有限 history 已严格推进超过该编号的旧帧。最新帧仅在原生终态后检查。双文件同时持 Win32 GENERIC_READ / FILE_SHARE_READ 句柄后验证完整字段、原体节点、原壁节点和原壁面及同阶段温度配对；不把稳定长度、半写文件或 latest 别名当完整场。由这一策略导致的保存间隔及至少下一历史行检测延迟必须明示，不能证明未保存的瞬时温度。

唯一测试输出为 `outputs/v174_validation/domain_guard01`。测试脚本和守卫准确源随输出快照保留。测试覆盖：闭区间端点、上下越域；实际 small02 的编号 2/3 只读回放（原缺 0 帧失败不改变）；真实 Windows 已有写者/新写者排斥；截断、错行数、NaN、错 PointID、错表头、错 VTK、错配对；历史不完整及最新编号延迟；异步非阻塞轮询、已检查帧不重读、终态检测标志；单 helper 超时和累计预算、父截止以及仅自有子进程回收。任何失败均保留，不据此重算原生任务。

writer 源先与新包 build01/source_tree.json 的 SHA256 逐项核对，再记录精确路径、行及文本。运行中旧编号不重写的前提只适用本具名 fresh / 单区 / steady 合同；新启动路径或 writer 改动必须重新审核。
