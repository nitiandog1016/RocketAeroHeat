## 3. 空间表和实际回执

现有C++ `RAHAxialWallTemperature.hpp` 对表头、两列、正有限温度、递增X、至多10000行及全节点X覆盖严格检查；**它不校验60–2000K物性范围**。新Python预检须补模型温区，不要说原C++已覆盖。还应拒绝非ASCII/BOM异常表头、重复X、NaN、覆盖不足、改SHA、空表和额外列。

`audit_applied` 已按原SU2网格的显式全局编号收集 `wall`，核对回执ID集合唯一且等于全壁、XYZ与原节点一致、逐点Tw与X线性插值一致。它能处理新单wall三维网格，不需改变旧多marker审核。表和回执的实际数值要独立比较，而不只比较模板字符串。

130站表在3226壁节点与原Tw(s)完全一致是v170几何证据；不自动证明新C++已读取它。新运行必须实际产生 `rah_wall_temperature_applied.csv`，保持给定值身份。粗fixture可采用与节点不完全重合的X断点测试插值，再核对真实网格的节点表。壁面流体温度即使不同也不能事后改成给定Tw；严格热流审核用实际邻点温度、实际导热率和该点给定Tw。

## 4. 保存合同需要修正的具体语义

旧NACA `inventory` 的期望列表是 `range(last_history+1)`，只支持每步保存；旧wall集合按 `wall_`前缀，不能用于新单wall。层流字段及同次流动阶段可复用 `load_state`，仍不能套用SST的阶段k列。

新inventory至少应：

1. 校验所有有限历史行从0连续、无重复、更新步号为整数；保存步在预算内且有同索引历史。源/局部/累计步明确；首次初猜运行累计从0起，不称复用旧整箭迭代。
2. 正常终态的计划集合为0、周期步及实际最后有限步，最后步若非周期仍须完整对。达到原收敛条件提前结束时按真实末步核验，不能强求`ITER-1`。
3. 异常终态只要求历史内已应出现的周期场，异常瞬间完整场保持未知。不要无条件把`lastFiniteHistory`加进“缺失计划场”，否则会把合法的稀疏异常终态误标为丢失计划保存；可单列“无完整异常末态”。
4. 对体场与表面逐字SHA、原节点坐标/编号、准确具名列、有限且正状态逐项核验；配对不完整/截断明确拒绝。
5. 正常成功还必须没有timeout/cancel/outputBudget/supervisorError、全部输入稳定、热表实际回执通过；“native exit0但后审核失败”保留双重状态。
6. 当前 `output_plan` 的27列×32字节保守估计可复用给层流，须改成层流stage，包含首/周期/正常末、最终别名、history/log及输入回执；输入网格/初场的长度另列。不能为了更省空间未经证据减少标量字节数。

旧层流字段为同次保守量/原始量，不需要SST前帧k。原生17位输出与严格热审核2e−10保持。

## 5. 有区分力的小型组合检查

不需要重复原多marker三更新。建议固定一个新单wall小fixture，在同一初场/配置下做四个明确组合：旧observed标量控制、新包无表标量、新包常量表、新包非均匀表。每个4更新、every2，能核对0/2/3包含非周期正常末帧；每项≤30秒/2线程/32MiB，具体允许项须由事前计划确认。

比较范围分别是：

- 旧/新无表共同原始字段一致，证明文件功能未激活时的目标路径保持；不是普遍证明整个二进制数值等价。
- 新常量表与新标量边界相同，在同一空间wall节点编号上比较温度输入和保守/表面字段；不以不同marker拓扑的旧运行做此对照。
- 非均匀表真正含不同Tw及插值节点，全部实际输入回执、同阶段EOS/能量/热通量/总功率通过，并能拒绝把标量占位误当实际Tw。新表必然改变边界，不能要求其流场等于标量控制。
- 非法表、覆盖不足、漏custom/错marker、旧包夹带表、错误Mach向量、残差−7、未登记频率、缺首帧/周期/末场、异常末态、重复启动、超预算及继承环境变量等分别做具体现成前置/离线测试。禁止为预检拒绝启动真实CFD。

完整旧输入中的可变源SHA跨版本变化时，不能宣称旧全合同重新通过。可以绑定旧准确源做只读前端分派/拒绝回归，并明确是否使用末端替身。
