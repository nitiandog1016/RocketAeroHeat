# 有界输运启动前：守恒未知量的密度链式法则

原PLAN中的“直接使用官方BOUNDED_SCALAR做一次三维对照”尚未启动。在配置前审查中发现，SST内部未知增量为rho*k/rho*omega；有界散度修正残差为−phi*div(massFlux)，其对守恒未知量的导数应为−div(massFlux)/rho。固定v8.6.0源中的着色边、归约边及远场修正对角使用−div(massFlux)，缺少这个换算。这个问题只涉及拟用的新有界路径，不能用来解释v130的SCALAR_UPWIND失败。

已从原CScalarSolver.hpp提取原函数体及四行修正后的函数体，用同一C++编译器执行密度0.02、1、5的中心差分核对。原函数导数/差分之比为rho；修正后为1。一个独立纯对流隐式更新反例在rho=.02、V/dt=1、入流质量通量绝对值1、旧phi1/入流phi0时，原对角给phi_new=−24，正确链式法则给0.0196078431。只执行了准确源码片段和独立代数反例，不是完整SU2运行；不能由此宣布修正后全SST正值或物理资格。

补丁只给Conservative=true的散度修正对角除以当前密度，残差、源项、下限和松弛不变。Conservative=false（如SA）分支不在本研究资格范围。源码树当前没有被改变，候选补丁在third_party/su2_bounded/bounded_conservative_jacobian.diff。

## 在任何新构建/原生启动之前修订预算

1. 停止原未修正官方有界方案，不盲目执行PLAN。先核对已有编译缓存、依赖和来源；允许一次2线程/最多720秒的受控编译并独立安装，不覆盖官方/历史运行包。全部改变和原源须记录，结束后还原被临时修改的源码。若依赖/预算不足，停止，不连续重编或接受混入旧实验对象的产物。
2. 构建通过后，先用小型既有平板初态作官方与新包的SCALAR_UPWIND同输入两步兼容检查，再用新包BOUNDED_SCALAR作两步接口检查，各最多30秒；不称公开热流验证。未改路径若不能保持可解释的一致性，停止三维候选。
3. 只有构建/兼容/热阶段通过，才执行原PLAN的一次完整域100更新/360秒；保持原初态、复用v130控制、原面积和事前筛选，不再重复控制。新增原生总预算450秒；编译720秒另列。新运行目录逻辑预算仍900MiB、小证据12MiB；编译缓存增量单列，不新建重复完整源码工程。
4. 适配器必须显示“受控有界标量守恒Jacobian修正”，不能冒充未改官方包。代码、数学片段检查、完整引擎兼容、三维筛选和物理资格分别报告。
