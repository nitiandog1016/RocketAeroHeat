## 六项代码事实

1. **热流覆盖是已有工程有效面掩码的面积统计，不是独立物理认证。** `analyzeHeatingCoverage.m:19–24`直接将`h.eligibleFace`作为`computed`，核对面积正值及未解掩码互补；`:120–148`按首要原因排他分类，保留全部重叠flags，明确为工程诊断；`:154–161`以`sum(area)`为分母输出computedAreaFraction。函数没有读取实验误差、网格独立或物理资格证书。因此旧66.5626%只能表示对应快照中工程方法接受的热流面积，不能称66.5626%已获得独立精度认证，也不能依据该比例默认真实20°分离/底面/突起合格。

2. **查看器已有逐变量可用状态和真实面积分母，但尚无独立的可执行资格台账。** `buildAerothermalViewerData.m:7–11`从原V/F算真实三角面积；`:33–56`把压力状态定义为0未解/1工程计算/2给定，接受`p.fieldStatus`覆盖，给定尾底/背风Cp单列；`:99–111`另由热流`eligibleFace`生成状态，Kinney另标工程对照。`:163–175`逐区域、逐字段统计三类面积，`:230–237`存逐变量方法/范围/原因及面积比例；这里没有`qualifiedArea`或逐变量物理验收对象。`:259–277`进一步声明外缘压力、表面压力、热流、给定Tw、求解壁温不能混用身份。现有压力计算50.2710%/给定49.7290%与热流66.5626%是不同账，压力和q不能共用资格或互补补齐。

3. **普通“solved”是快照结构接收状态；研究结果有独立路径和禁止自授资格的门槛。** `aeroHeatWorkflowState.m:191–204`在几何一致、字段结构通过后设`solved`；`:345–389`主要检查逐面元长度、有限/NaN与压力0/1/2、热流eligible掩码一致，并不验证物理精度。`:205–228`独立接收researchResult，要求`productionQualified=false`及`eligibleForSurfaceCoverage=false`，然后清空普通result。`:269–290`失效上游输入会清结果，版本/求解ID拒绝过期返回。新台账应复用这些失效规则，不能将`solved`或`research-ready`直接解释为资格通过。

4. **完整壁映射和有符号热功率闭合只证明映射身份，不给p/q统一授予物理资格。** `mapSU2WallResult.m:6–21`要求壁节点唯一匹配及原连接一致；`:23–32`投影p/q/T并分别核对物面平均q积分、引擎节点合成面积热负荷。`:33–44`明确区分heatFlux与heatLoad、流体节点T与给定Tw，始终输出`eligibleForSurfaceCoverage=false`、`productionQualified=false`、`newQualifiedRocketArea=0`。热功率守恒检查没有检查压力误差/压力力矩精度，不能因q映射守恒就把p标为已验证，也不能把全壁有限值当全壁物理认证。

## 下一项最小可执行边界

先新增一个**纯数据台账构建器与明确适配层**，读取现有原面结果和已存在的准确证据，不求解、不修补场量、不改变原面积分母。建议边界为`buildAerothermalEvidenceLedger(mesh, evidenceRecords)`：

1. 用原V/F及面序身份、冻结工况、热模型/能量参考、给定Tw身份和来源SHA构成结果身份；始终以全部原面面积求和作分母。原19752面完整几何是该实际对象的验收条件，不能用NACA/平板或删去困难区域后的几何替换。
2. 第一层保留既有**数值可用状态**：压力0/1/2，热流eligible/NaN；原生研究场另标researchSaved，不加到工程computed份额。第二层单列**物理证据状态**：逐变量、逐区域的未审核/通过/失败，附来源、验收规则及明确拒绝项。初始全部资格面积为0；旧工程掩码、有限值、exit0、映射闭合和残差通过都不能自动变成物理通过。
3. 每条物理证据记录至少包含变量键、原面ID集合/区域标签、模型和工况适用范围、保存场身份、原门槛、实际结果与证据SHA。压力记录审压力与对应边界/区域条件；q记录审热物性、实际热边界、热流参考与近壁等必要条件。共同的几何/运行来源可以引用同一证据，但两变量必须分别判定；表面p、外缘pe也分开。
4. 输出逐区域/逐变量的computed、prescribed、missing与qualified面积，以及拒绝原因和证据链接。前三项独立闭合到同一个总面积；资格是另一个集合统计，不能与可用面积相加。几何主区域可作排他分组，分离/再附/底面/突起等标签可以重叠，但汇总资格时按原faceID取并集去重，不能重复累计面积。
5. 用一个很小的纯数据反例集验证：压力有限但q未知、压力给定但q计算、q映射/残差通过但物理失败、同面重复证据、错面序/错工况/旧源拒绝、研究数据不挤进工程覆盖。然后只接既有查看器字段和导出中的台账展示，保持当前0/1/2及旧CSV含义兼容。无需再次运行CFD、回归长任务或重新搭整套UI。

这一步完成的验收是“统一、可复核、不会相互冒用的区域证据和面积账”，不声称提升了物理解面积。真正新增资格仍须后续对应区域/变量取得独立物理证据。

## 实现风险

- **把证据不足改成给定或工程计算**：现有`add()`在`:186`会把非有限值降为未解；资格层必须同样缺证据即未审核，不能按方法名或全局`productionQualified`猜结论。
- **一份报告覆盖不相容变量/区域**：同一个SST或层流结果可能通过p的条件而q失败；鼻尖或前缘未合格不能由中段参考推满全域。判定必须按变量和实际面集落地。
- **区域交叠与分母漂移**：同一face可能同时具有几何区域和物理现象标签。主分区统计与多标签查询应区分，资格并集不得重复计数，也不得删去未知底面/突起来缩小分母。
- **SHA与面序/时间身份脱节**：只核节点/面数不足；需要冻结V/F面序、工况和实际保存帧。历史末步、最后完整帧、冷重启累计步保持独立，不能按显示最近一次推断。
- **误用“通过”字段**：`interfacePassed`、`savedFrameInterfacePassed`、`checkpointResidualPassed`和`productionQualified`含义不同；适配器须显式映射，不能用泛型`passed`自动升级资格。v174已有案例证明异常终态仍可有严格通过的保存场一致性。
- **副作用扩大**：构建器只读；不触碰生产模型、默认数值、OpenCode修改或已关闭NACA计算入口。缺少支持合同则记录unsupported，而不是绕过旧拒绝再读未知列。
