# B 型热敏珠在同一启动时刻的时间步长比较

时间步长减半后，6 m/s 热敏珠在距构造初场 **7.809360865 µs** 的 5,216 个原面全部完成同刻对照。局部壁压最大差 **0.002772 Pa**，局部入壁热流最大差 **0.006122 W/m²**，放热峰位置相同。相对 v291 新增覆盖 **0 面、0 m²**，此版本为原有 **3.0898302614 × 10⁻⁶ m²** 完整面积提供第一组时间步长敏感性证据。3 m/s 热敏珠及自绘模型均新增 0 面、0 m²。局部实验联合验证面积仍为 0 m²。[逐面数据包](../../../cases/thermistor_b/startup_6ms_halfsteps.zip) · [同刻差异](evidence/comparison.json)

| 两个半步减一个整步 | 面积加权 RMS | 局部绝对最大 | 加权 RMS 占参考尺度 |
|---|---:|---:|---:|
| 壁压 | 0.0008857 Pa | 0.0027720 Pa（工作台面元 376） | 动压 21.24 Pa 的 0.004170% |
| 入壁热流 | 0.0010333 W/m² | 0.0061219 W/m²（面元 27） | 整步热流峰值幅值的 0.00001564% |
| 首层流体温度 | 4.69 × 10⁻⁸ K | 4.36 × 10⁻⁷ K | 给定温差 10 K 的 0.000000469% |

整步与两个半步的峰值入壁热流分别为 −6606.75479 和 −6606.75513 W/m²。两次峰值均位于工作台面元 **5211**。整珠向空气的放热由 10.726572556 mW 变为 **10.726572344 mW**，相差 **−0.2125 nW**。压力和热流的 RMS、局部最大差及总功率差均低于事前尺度。两档步长只支持本初场、本时刻的敏感性判断；收敛阶、近壁空间误差和发展后尾迹仍待检验。[峰值、面积、时间层及功率](evidence/comparison.json)

第一次观察回放在第 261 次装配读取了更新后的流动量和更新前的标量。23,258 个节点的压力与官方终帧之差超过事前的无量纲 1e-8 容差，其中包括 1,449 个壁节点，最大差为 2.67 × 10⁻⁸。观测压力、速度与观察器第 261 次终场逐点相等。SU2 的 CFluidIteration 先推进流动再调用辅助标量方程，CSingleGridIntegration 对标量先作空间装配再作时间更新。这解释了两类量对应的迭代阶段。该回放的热量余额虽小，其状态身份检查失败，原回执已留存。[逐点诊断](evidence/assembly.json) · [原拒绝记录](evidence/first_energy_rejection.txt.gz)

## 工作台与复现

在主侧栏选择 **B 型热敏珠 → 查看 6 m/s · 同刻时间步对照**。默认显示入壁热流差。下拉菜单可切换到壁压差和两个半步的绝对压力、表压、入壁热流及首层温度，主场与对照场可以共用色标。差值统一为两个半步减一个整步。给定壁温仍为 303.15 K。MATLAB 也可直接生成离线三维页。

```matlab
[mesh, report, page] = runThermistorBeadCase([], 'timeSteps6');
```

验收从实际 MATLAB 主窗口进入该模式，核对全表面数据、面元拾取、PNG/CSV 下载时刻及 X = 0.172 mm 截面的 121 条交线。第一次回读中 MATLAB 自动识别 CSV 表头失败；验收脚本显式采用逗号及文件首行后，通过全部原面值和离线数据脚本回读。原整步模式单独复验。图中所选面元 2538 与最大热流差的面元 27 分别核对。[界面回执](evidence/ui.json) · [差值图](evidence/heat_difference.png) · [首轮界面回读记录](evidence/first_view_log.txt.gz)

两次正式推进共 **499.06 s**，读取壁反力的回放和独立控制共 **729.25 s**，其中包括首次未通过的混合阶段回放。各原生进程单线程，进程树峰值约 1.18 GiB。编译和链接共 35.54 s（含一次编译失败）。正式配对和独立热流差复算分别为 3.41 s、3.55 s。最终 UI 验收 69.86 s。开发与归档没有单独计时。大型体场、原生反力和构建缓存保存在 E 盘，未随 Git 备份。[运行回执](evidence/processes.json.gz) · [本地文件及校验值](evidence/local_assets.json)

原始运行采用以下顺序。每个命令创建新的输出目录。复现须恢复 v289 的已绑定输入、v291 文件和 SU2 单对象构建缓存。先用 `run_step.py 1` 从原种子推进，用 `check_step.py state 1` 验收；初始回放和独立壁反力分别用 `check_step.py observe 1`、`release 1` 获取，先用 `build 1` 生成观察器。保留原拒绝，`check_assembly.py` 核对节点与源帧。随后依次执行 `read_endpoint.py build`、`observe`、`audit`。在独立的 `pair/first_energy/accepted.json` 引用该次合格回执，`run_step.py 2` 通过 `--previous` 读取它。使用 `check_step.py state 2`、`build_second_readout.py`、`check_step.py observe 2`、`release 2`、`energy 2` 完成第二半步，各第二步核对命令使用 `--root outputs/v292_validation/pair`。最后由 `compare_surface.py` 比较并打包，`check_heat_difference.py` 回读独立反力。每阶段的完整实际参数可从进程回执恢复。
