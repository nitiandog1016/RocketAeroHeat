# 构建后验勘误及最后一次真实验证

`diagnostic_format_build`确实编译了修正消息的FlashRoutines对象，但安装步骤对普通静态库只执行`ar s`，没有替换成员。SU2核心库是薄归档，CoolProp库却是普通归档。后验发现recon-v2的两个二进制均与recon-v1相同。因此其逐字节物性/流场对照不构成修正后验证，actual03的22.562秒失败也是旧二进制复跑。这是本轮构建错误，不解释成新的物理失败，原证据和错误脚本均保留。

纠正采用已编译对象执行`ar r`真正替换成员，并独立提取比较对象SHA。第一次通过`ar p`管道校核受Windows二进制LF→CRLF转换影响而失败，保留该次状态；随后明确从替换完成处继续，在独立目录原生提取后逐字节通过，没有重复编译。两个新二进制SHA必须与旧包不同。

独立同输入DP超温程序在原库输出`other-exception argument not found`，新库输出`typed-OutOfRangeError DP yielded T > 1.5Tmax...`。据此证明修正真正进入了运行包，而不是只看编译退出0。新包独立命名`rah-coolprop-recon-v3`，v1/v2及原包均冻结；原源码已归还，编译缓存仍含本轮受控对象，未来重构不能假设其等于归还的源码。

最终包对全部210914节点的原PT/DE查询逐字节保持（另有一个来流PT），20步正常控制8.578秒，原生场/表面字节一致且守护未触发。只在这些检查和原生异常类型证明之后，才允许actual04同初态/网格/配置的20步、600秒验证。actual03的无效复跑计入总代价，不隐去；不再追加物理参数或容差改动。

归档第一次在actual04运行中触发终态拒绝，已复制的少量瞬时文件另存`preterminal_snapshot/`，最终证据独立保存；不得以瞬时回执冒充终态。
