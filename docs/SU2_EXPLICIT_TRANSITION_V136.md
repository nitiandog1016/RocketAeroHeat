## 1. 先排除输入表面自交

只读定位显示，v135的98个异常内面均不包含金字塔顶点，中心距最近金字塔顶点7.708—50.321mm。不能仅凭“用了自动金字塔”就认定金字塔方向是唯一病因。

按[事前计划](validation/v136/PLAN.md)安装独立CGAL 6.0.1.post202410241521 Windows wheel和Python3.11.9嵌入式运行时，23.922秒导入通过；没有改变现有Python或MATLAB。wheel与PyPI发布SHA256匹配，Python来自官方HTTPS地址并记录下载SHA；没有声称已做独立签名验证。运行时范围限于已测几何检查，未把其他CGAL包或四面体重网格说成已集成。

四项实际CGAL检查通过：规则闭合四面体和正常共享边各0交对，明确穿越及共面重叠各1交对。读取后逐节点坐标、逐面循环方向和编号与输入完全匹配，没有先自动修复或平滑。原壁19752面、v133外壳19752面、v135终止接口22144个审核三角面均为0自交对；三个完整实际检查连同准备共5.094秒。四边接口仅在审核中按面心扇表示，不把真实共享四边面拆开接入求解。

使用的是[CGAL自交API](https://doc.cgal.org/latest/Polygon_mesh_processing/group__PMP__intersection__grp.html)及[官方Python绑定](https://github.com/CGAL/cgal-swig-bindings)。事前计划中的版本化6.0.1文档URL本轮未能访问，实际能力核对用上述当前官方页和固定本地模块/实测；不冒充读取了不可访问的网页。

第一候选通过拓扑后，独立SVD检查发现205个坏单元中204个的四顶点均位于固定接口，204个在鼻部，另1个在主体。对任一固定三角面，把第四顶点自由选取时的最大SICN为`3/(1+κ+1/κ)`，κ为该面相对等边参考的两奇异值之比。两项解析极限及各100个随机顶点检查通过；22144个接口面该上界最小0.189527，没有单个面必然迫使质量低于0.1。此结论仅针对单个孤立三角面，**不证明全部固定边界同时能达到质量门槛**。

在[独立HXT事前计划](validation/v136/HXT_PLAN.md)中，只改变外域算法，直接复用已审598金字塔和三角边界，不重新构造/审核几何，不扫描尺寸/层数。其依据是[Gmsh4.15.2官方算法说明](https://gmsh.info/doc/texinfo/gmsh.html#Choosing-the-right-unstructured-algorithm)：HXT为另一套并行Delaunay实现；显式过渡已将外域接口变成全三角面，才具备这一对照条件。两候选各只执行一次，均未采纳或改默认。

## 4. 下一起点

不重跑本轮两种算法或已过CGAL/UI，不做同高度、层数、尺寸扫描。当前瓶颈已从内部拓扑转为**固定过渡界面附近的低质量四面体及规模**。HXT475个坏单元都在鼻部，其中184个含4个固定顶点、257个含3个、34个含2个；不是简单只移动自由节点即可保证解决。

优先评估成熟的局部四面体重网格：以规模合格的显式Delaunay完整域为保留基线，限定坏单元及邻域，保持金字塔/棱柱接口和远场的节点及三角连接，以内部边分裂/翻边/局部重连处理低质腔。官方[CGAL四面体重网格](https://doc.cgal.org/latest/Tetrahedral_remeshing/index.html)支持局部选区和`remesh_boundaries(false)`；**本轮只集成了自交检查，重网格C++工具链仍未集成/未测试**。接入前明确输入恢复、固定面、单元正性/完整配对、规模/质量和时间/磁盘预算，先做有独立真值的局部检查；不能直接套纯四面体工具破坏共享接口。

若固定接口的角度或局部拓扑确实构成质量障碍，应基于证据改为沿轴向分布的平缓层终止或相容连接，保护原壁及近壁，不能无限扫描同一陡台阶。新方案须运行前定义，不追改本轮失败。完整几何通过后才进行一般棱柱/金字塔初场迁移与有限真实流场；原迁移仍不支持19层局部终止，不能最近邻补值。

真实20°全面积、分离再附/底面/突起、可闭合公开热验证、高效物性与科研UI继续最高，累计热量后置。网格/UI成功不是新增物理解面积，原−8和旧失败保留。
