# v211：真实区域NK/SA资源账与完整扩域方案的关闭

2026-11-08。沿用低成本外流＋工程边界层＋必要局部黏性CFD。**原7838面区域的基准层域尚未被必要下界排除，但原设计要求的9678面扩域验证，连不含任何ghost的必需载荷也超过8GiB。因此关闭该具体配置下的“基准＋扩域”完整方案，不启动试运行制造OOM。** 不等于所有Eilmer配置或所有局部域均不可行，也不是要求用户购买更大主机。

本轮没有完整引擎构建、体网格生成、CFD、MATLAB或主UI改动，没有新增可信热面积。总目标active，工程区域和科研UI继续独立推进。

## 1. 准确对象布局，而非按旧峰值或壁面积推算

固定上游`f53f4609a0331d48efee69a4e4f3c3598378cc03`、原LDC1.41.0、v197官方复数NK编译开关和几何修正。v210隔离气体复用，未再做物性查询。单次编译期`sizeof/classInstanceSize`查询使用`-c -o-`，不链接或执行流动引擎，不分配全域。

监督1.719633秒/入口2.795323秒，实测组RSS峰502841344字节，379输入稳定、进程组清空。此峰仅属于类型查询，不能用于估计流动峰值。20个定向源文件分两次提取共0.234788秒；开发、阅读与协调墙钟另计。

SA-Edwards为一条湍流方程，三维五条流动守恒方程加SA共六条。运行关闭MHD/多温/多组分方程，但官方编译开关保留的inline字段仍占内存。原生NK强制两层流动状态；原`allocate_dense_celldata`每层数组分配C×6×2项，共四个数组，即8×C×6×16字节，不能按理想紧凑存储缩算。

GMRES和ILU实际是double，不能随复数状态统一乘二。ILU0只计一次CRS，原位分解没有另一个同规模L/U副本；`external`声明不代表已分配，矩阵临时点图也没有混入常驻下界。GMRES固定继承v197的50维/零重启/复数Frechet/非FGMRES，此结论不外推其他线性配置，也不以减少维数来直接授予收敛或资源资格。

## 3. 必要载荷与决定

逐项账只计并存且独立的payload，不含GC取整、数组元数据/容量、页空隙、外域、额外ghost/边界对象、临时图、I/O、运行库/栈和峰值余量。

| 范围 | 必要载荷，字节 | GiB | 结论 |
|---|---:|---:|---|
| 基准层域，含设计ghost | 7,470,117,541 | 6.957089 | 未排除，绝非可运行证明 |
| 基准层域，完全去掉ghost | 7,243,472,425 | 6.746009 | 内部资产的保守下界 |
| 原扩域层域，含设计ghost | 9,218,635,501 | 8.585523 | 超过8GiB |
| 原扩域层域，完全去掉ghost | **8,943,351,825** | **8.329145** | 仍超过8GiB，完整方案关闭 |

无ghost扩域至少超出8GiB上限353,417,233字节，约337.045MiB，还未计外域和分配开销。不能据此谎称已测到OOM/实际峰值，也不能因基准剩约1.04GiB就先启动；原设计的截断误差验证不可省略。

按所有者独立重组，得到完全相同的整数和：

`13217*C + 3003*F + 745*V + 3170*N + 32*CV + 124*CF + 24*FV + 584*(N+2*Fi) + 344464`。

C在层域账取N+G，在保守内部账取N。584项包含最近邻单元模板与六变量CRS；50维GMRES等N项已经在3170项内。未将源流动对象与指向它们的slice重复计入。该公式是准确配置的必要条件，不是任意网格/配置的峰值模型。
