# outputs 目录用途与保留规则

`outputs` 不是软件源码，而是历次运行留下的数据。**日常运行不要求保留全部历史输出；继续当前研究仍需要选定输入和当前状态。**

| 文件类别 | 具体用途 | 是否需要留在本地 |
| --- | --- | --- |
| 当前几何、工况、接受状态、方向及检查点 | 继续计算与恢复中断 | 当前研究继续使用，保留 |
| 历史独有MAT结果、失败证据、参考数据 | 复核已报告的科学结论 | 暂留；如转移到其他存储，须先核实完整副本 |
| 旧矩阵、分解缓存、重复导出和工程包 | 提速或历史交付 | 核实可重建/已替代后回收 |

硬链接的多个路径共享一份数据，不能将路径累计量当作实际可回收空间。以下旧轮次记录保留为各自时点，不能相加推算当前大小。

## 是否需要把整个目录保存在本地

日常运行程序需要项目源码和选定模型，不要求随软件附带全部旧输出。但正在进行的研究还需要本地的当前状态、几何、检查点，以及用来核对已有计算结论的独有历史结果。这些文件未上传GitHub；直接删除整个`outputs`将失去原状态续算与部分验证能力。

旧矩阵/分解因子属于可再生缓存，确认不再使用且输入、构造源码已保留后可以删除；代价是以后复查时重新构造。历史日志、小型SHA回执和独有结果继续保留。已有硬链接按不同路径展示，却共用一份磁盘数据，因此删除一个重复路径通常不会释放相应文件长度的空间。

本次新清理的五项因子来自`patchhierarchyreal01`、`blockfillreal01`、`overlapFreal01`、`floworderfactor01`和`spatialreductionreal01`。五项旧试验的实际进程均已终态、exit0且源码稳定；原数值方向、结果、输入矩阵及依赖的其他因子保留。原构造源码由已发布Git字节或小型raw原文绑定。历史矩阵审计需要按记录在新目录重建构造阶段，不能直接运行已缺缓存的旧审核命令，也不能承诺重建MAT的历史SHA相同。此次没有删除独有的Arnoldi失败证据或中断检查点。
