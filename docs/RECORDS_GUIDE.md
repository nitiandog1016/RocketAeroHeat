# 记录维护：短入口、完整证据、单一当前状态

此规则用于防止长对话压缩后重复计算、混淆研究资格或执行旧计划。2026-11-16经用户要求整理；不改变科学方程、验收门槛和具体运行预算。

## 文件职责

| 文件 | 只维护什么 | 更新时机 |
|---|---|---|
| [AGENTS.md](../AGENTS.md) | 长期执行约定、恢复顺序、保护规则；≤8 KiB | 用户规则或协作方式改变时 |
| [PROJECT_GOALS.md](PROJECT_GOALS.md) | 当前目标、技术路线、验收和职责；≤12 KiB | 目标/路线/验收有明确变更时 |
| [CURRENT_STATE.md](CURRENT_STATE.md) | 唯一当前交接：完成基线、进行中任务、证实/未证、下一步、关键证据；≤8 KiB | 每次阶段交付、切换、暂停/中断、关键状态变化时，替换旧状态 |
| `docs/validation/<iteration>/PLAN.md` | 执行前准确输入、对照、预算、停止及输出合同 | 运行前；追加更正另列，不能追改执行过的合同 |
| 专题报告＋同版本`NEXT_DECISION.md` | 实际实现/结果/限制、失败、采用/拒绝原因及当时下一决定 | 取得实际证据后 |
| [EXECUTION_INDEX.md](EXECUTION_INDEX.md) | 检索入口、版本报告/证据/下一决定的位置 | 新交付时增加一行链接，不复制长摘要 |

无需为每次工具调用写一篇记录。低影响文档修改只留变化说明及必要检查；数值计算按原科学合同留准确证据。历史NEXT_DECISION是当时决策，只有CURRENT_STATE明确指向的才是当前行动入口。

## 压缩恢复/重新开始时

先读三个短入口，再读当前具名决定/计划。核对Git HEAD与未提交差异；针对相关计算核对PID、启动时间/命令身份、日志是否变化、监督终态及源SHA。PID会复用，进程消失不能推出exit0或成功；缺回执时记录“终态未知”。已有计算运行中则接续观察，不能重复启动。不要每次全量读取所有归档或哈希所有大场。

文件和对话不一致时，以用户最新要求和实际证据校正；不要因新建版本目录或较晚文件时间就升级已交付版本。若其他聊天正在写同一入口，先读其最新内容、对比读取时SHA，合并新事实再写；不覆盖并发状态，不以自己任务结束为由终止别人进程。

## 每轮结束怎样写

1. 报告写清准确基线/提交＋dirty状态、改了什么/为什么、运行合同、真实结果与失败，列出已证实和未排除假设。小数据跟Git，大文件给本地路径/SHA/恢复说明，未备份如实标记。
2. NEXT_DECISION只写一项具体下一行动、适用输入、采用/拒绝依据、必要预算/停止条件和回主线条件；关闭的是具体组合，不把一次失败泛化成整个方法无效。
3. 更新CURRENT_STATE：完成基线、仍在进行的任务、实际结果范围、关键未知、暂不能重复的具体试验、下一步及保护范围。保存帧/接受步/原生终态/恢复态分列，不把通过软件检查写成物理通过。
4. 更新EXECUTION_INDEX中的链接。目标或长期规则没有变化，就不改PROJECT_GOALS/AGENTS。不再在文件首尾同时写多个“最新起点”。
5. 运行 `python scripts/checkProjectRecords.py` 检查入口大小、当前指针、引用和历史快照完整性。科学结论使用对应分支的验证记录。检查本轮差异，只提交本任务的文件。每个可交付的小版本按下节同步 GitHub。

当前页保留三行机器标记，方便检查：`records:last_completed=vNNN`、`records:active=vNNN`或`none`、`records:base_commit=<40位提交>`。它们属于CURRENT_STATE，不另建第二份当前状态JSON。文字内容应与标记一致；基础提交不必等于整个工作区的最新提交，需注明来源。

## 小版本编号与 GitHub 同步

每次交付代码更新（含小修复）使用小写 `v` 加十进制整数。核对本地提交、在研计划和远端标签后，取下一个未占用的递增编号。本次科研阶段已预留该编号时沿用它。同一阶段发布之后再交付代码时，发布号继续递增，计划仍可引用原阶段。源码提交标题以 `vNNN: ` 开头，发布标签使用同一编号。单纯文字勘误可随代码版本交付。

在 `main` 上完成适用检查后，记下发布提交的完整 SHA。用 `git tag vNNN SHA` 创建轻量标签，再用 `git push --atomic origin SHA:refs/heads/main refs/tags/vNNN` 同步主分支与标签（替换实际版本号和 SHA）。用 `git ls-remote origin refs/heads/main refs/tags/vNNN` 核实远端标签与发布 SHA 相同，主分支已包含该提交。遇到并发推送或标签冲突，先取回远端变更并重新核对，保留已有标签和提交历史。同步失败时交接中标记“待同步”。发布号标记代码快照，科研阶段是否完成以当前交接和验收证据为准。

## 最小交接内容

- 完成基线：哪个版本/提交；工作区是否另有未提交内容。
- 已证实：两三条关键结果，附原始证据路径；资格范围是什么。
- 未知/假设：哪些原因尚未证明，哪个门槛没过。
- 进行中：任务入口、准确输入/预算、进程身份或终态未知、最后观察时点。
- 下一行动：具体要做什么、怎样判定收益/失败、什么时候停止。
- 保护与交付：并发文件、大资产路径、当前同步限制。
