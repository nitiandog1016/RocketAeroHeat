## 热流状态阶段是下一项真实缺口

固定源码`CFluidIteration.cpp`先调用流动更新，再调用SST单网格更新；`CMultiGridIntegration.cpp`在流动更新末尾计算primitive和热负荷，然后SST才更新k/ω。因此同一个打印迭代号的ρE、k和热流不一定来自同一个耦合阶段。保存壁面k几乎不变，壁面p/T EOS可以通过，而近壁内部k变化会使热梯度反算不一致。

当前源码顺序支持这一机制，但缺少前一阶段k98或精确原生邻点温度，**尚不能据现有终态文件证明逐点全部差值均由该机制造成**。只读量化见`split_phase_diagnosis.json`；原审核保持失败，不能把解释当成通过。

下一项须先设计一次有区别能力的原生单步阶段试验：复用本次99步SST状态，明确记录输入k、更新后ρE/k及原生热流/精确温度，分别按旧/新k重构；先定义身份、预算与原门槛，再实现独立诊断入口，不套用层流续算合同或伪造新模型转换。若需要额外字段，优先原生高精度输出；不先改求解器内核。此诊断尚未实施。

阶段对应关系确认后，修正SST保存/审核合同并接回主工作台结果、原面CSV与截面，再讨论完整域收敛/公开热流/分离底面。不得重跑本轮相同100步、单纯续时/加层、截图或HEOS构建。
